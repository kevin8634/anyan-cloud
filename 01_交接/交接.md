## 1. 开工流程
1. 解压最新工程包（含 .git）→ `git log --oneline -3` 确认最新 tag。没有 .git 时 `git init` 并给当前状态打包内版本号的 tag。
2. `npm install`；`bash tools/setup_env.sh`（chromium + arm64 依赖库 + 中文字体 + openpyxl）；测试前 `export LD_LIBRARY_PATH=/tmp/libs/usr/lib/aarch64-linux-gnu`。
3. 读本文件第 4–6 节，按「下一步」做。

## 2. 规则（Rhett 定，优先级从高到低）
- **顺序交接**：同一时间只有一个账号开发；版本号一条线递增，不开分支。存档版本只在需要时 +1 并写迁移。
- **推进时机**：Rhett 说「开工 / 继续迭代」才推进，不建定时任务。
- **额度（Rhett 2026-11-01 00:17 定，所有账号、所有窗口通用）**：**日额度剩余 ≤ 10% 或总额度剩余 ≤ 8% 立即停手**：停在能跑通的状态，commit（+ tag 如已成版），同步云盘。**接近红线时提前写交接**（docs/当前状态.md 顶部 + 本文件，传云盘 01_交接）。宁可少做，不留半截代码。每版目标约 8% 日额度。
- **每版交付**（全做完才算交付）：测试全过 → `version.ts`（GAME_VERSION + 更新日志）→ `docs/版本记录.md` 加一行 → 本文件第 4、5 节 → commit + tag → 工程包 zip（含 .git，不含 node_modules / dist）+ **本体离线版 + DLC 离线版** → 回复 Rhett：额度（日 / 周期百分比）、已完成、未完成、下一版预估。
- **DLC 铁律**：DLC 内容只放 `src/dlc/dlc1/`，本体代码不出现任何 DLC 文字（`tools/check-purity.mjs` 检查）；不装 DLC 时本体行为不变。
- 手机 30 帧；大的设计改动先列改动表给 Rhett 确认；新内容先出概念图确认；数值平衡整体暂缓（Rhett 10-22）。
- **绑骨标准（Rhett 2026-11-01，所有账号含长副本 raidA）**：会动的模型必须先绑骨、出 GIF 给 Rhett 验收后才进游戏；静态模型 + 整体晃动不算动作；纯程序化自动绑骨在 Lux3D 模型上会拉坏，只作回退。做法与验收见 `docs/设计/绑骨标准.md`。同步云盘时要在交接里写明这是标准。
- 换模型：不要 Q 版 / 拼装几何体；免费找不到先用不可商用并登记 `assets/MODEL_SOURCES.md`。
- **资产双包（Rhett 10-24）**：`assets/` = 原有资产包（商用默认，冻结不覆盖）；`assets_aholo/` = 比赛资产包（Lux3D 生成，只用于参赛版）。比赛模型不得覆盖原有资产；商用时换回原有资产包。细则见第 12 节。

## 3. 目录与命名规则
```
build-web.mjs / gen-assets.mjs / package.json / tsconfig.json / README.md   ← 根目录只放这些
src/core/        引擎无关逻辑（PascalCase.ts），不 import data / web
src/data/        数据表（snake_case.ts）
src/web/         浏览器表现与界面（小写.ts），main.ts 通过 CX 上下文分模块
src/dlc/<包id>/  内容包全部内容（manifest.ts 挂到 core/ContentPacks）
src/sim*.ts      命令行断言测试（npm run <名>）
test/            浏览器自动化测试（playtest.mjs、*-check.mjs、load.mjs）
dev/             手动工具：smoke.mjs、*shots.mjs（截图）、sfxcheck.mjs；dev/shots/ 旧截图脚本
tools/           生成 / 构建辅助：check-purity、setup_env.sh、gen/、optimize-*.mjs、pack-ubc.mjs、art.py
assets/          素材；来源登记 MODEL_SOURCES.md / ART_LICENSE.md
web/             构建产物 index.html（本体）、index_dlc1.html（DLC）
docs/交接.md     唯一交接文件（本文件）
docs/版本记录.md 每版一行的台账
docs/设计/       现行系统设计，一个系统一个文件
docs/攻略/       玩家攻略页与配图
docs/归档/       过期计划、旧交接历史、patches（只读）
```
- **文档命名**：中文主题名，不带日期和版本号（`野外地图.md`，不是 `v0.9.3_野外地图升级方案.md`）；版本和日期写在文件内。一个系统只有一个设计文件，改设计就改原文件；数据表用 `表_<内容>.xlsx`。
- **不再新建**：「换号交接」「XX 交接计划」「后续路线_日期」「迭代总表」之类文件。计划写进本文件第 5 节，设计写进 `docs/设计/` 对应文件。过期文件挪 `docs/归档/旧计划/`。
- **代码命名**：新模块按目录的既有风格；DLC 文件放 `src/dlc/dlc1/`，按系统命名（`hunter.ts`、`coffin_fx.ts`、`domain.ts`）。
- **发布物命名**：`暗岩传说_<版本>_工程包.zip`、`暗岩传说_<版本>_本体.html`、`暗岩传说_<版本>_DLC.html`。

## 12. 资产双包规则（Rhett 2026-10-24 定）
目的：比赛要用 Lux3D 生成的模型，但这些模型的商用授权以 Aholo / Lux3D 服务条款为准、尚未核实；原有资产（KayKit / Quaternius CC0、Quaternius QAL、Mixamo、本项目 TRELLIS）商用授权已登记。两套分开放、可随时切换，避免比赛模型带进商用版造成侵权。

### 12.1 两个包
| 包 | 位置 | 用途 | 授权登记 |
|---|---|---|---|
| 原有资产包（base） | `assets/`（快照 tag `assets-base-v1.2.20`，zip 在 files/releases/assets-base-v1.2.20/） | 默认构建、**商用版只能用它** | assets/MODEL_SOURCES.md |
| 比赛资产包（aholo） | `assets_aholo/`（与 assets/ 同相对路径） | 只用于黑客松参赛版（魔搭 Demo、报告截图、小红书素材） | assets_aholo/README.md 表格 |

### 12.2 铁律
1. **不覆盖**：任何比赛生成的文件都不进 `assets/`，不改、不删、不覆盖原有资产；要替换就在 `assets_aholo/` 放同相对路径、同文件名的文件。
2. **叠加构建**：比赛版 = 原有资产 + `assets_aholo/` 同名覆盖 / 新增；默认构建（不带比赛参数）必须和现在完全一样。代码里不写死比赛资产路径，统一由构建参数选包（实现待「开工」：建议 `gen-assets.mjs --assets=aholo` + `build-web.mjs --assets=aholo`，输出文件名带 `_比赛版`）。
3. **接口不变**：比赛资产必须沿用原资产的节点名 / 骨骼命名 / 挂点约定（rig.ts HD_RIGS、HD_ATTACH），替换只换文件不改游戏逻辑；对不上的先在 assets_aholo 侧适配（重命名骨骼、调原点），不改原有适配表。新增的比赛专用逻辑（铸造台等）放在可开关的模块里，关掉后与 base 行为一致。
4. **先登记再入库**：每个比赛文件在 assets_aholo/README.md 登记：用途、Lux3D 模式（Turbo / 标准）、文字提示或参考图来源、任务 ID、日期、积分、减面压缩参数、商用状态。没登记不许进构建。
5. **输入不侵权**：Lux3D 的参考图只用本项目自己的概念图 / 截图、CC0 素材或自己拍的照片；提示词不写现有游戏 / 影视 / 品牌的角色名、作品名、标志性设计（如「像某某游戏的某某剑」）。
6. **商用前**：商用版本一律用 base 构建；发布前检查产物里不含 assets_aholo 的文件（实现待开工：tools/check-assets.mjs 比对哈希）。若以后核实 Lux3D 输出可商用，个别资产要转入 base 须 Rhett 同意，并在 MODEL_SOURCES.md 补登记条款链接与日期。
7. **公开源码 / Demo 注意**：Mixamo 原始文件不可单独再分发（Mixamo_Anims.glb 是转换后的动作库，随游戏发布可以；公开源码仓库时在 README 写明来源与条款，必要时比赛源码包排除原始动作文件）；Bestiary（QAL）不可转售素材本身。
8. **交付命名**：比赛版文件名加 `_比赛版`（如 `暗岩传说_v1.2.21_DLC_比赛版.html`），和普通版分开存放；工程包两套资产都带上（assets_aholo 不进 .gitignore），恢复 base 只需不带比赛参数重新构建。
