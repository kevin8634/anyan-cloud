## 四、aholo 下 dlc_boot_order「service was stopped」根因与修法
- 根因：**内存**。守卫用 esbuild 把 dlc1 boot 的整张 import 图（含动态 import 的 web/*）连同 *.gen.ts 一起打包；`gen-assets.mjs --assets=aholo` 后 src/web/assets.gen.ts 约 458 MB、src/dlc/dlc1/creatures.gen.ts 约 136 MB data URI，esbuild 进程峰值约 6 GB，8 GB 沙箱被系统 OOM 杀（dmesg：Killed process esbuild anon-rss 4.9 GB）→ JS 端报「The service was stopped」。和 esbuild 版本（0.24.0）、游戏代码、测试判断逻辑都无关；空闲内存多时偶尔能过（所以像随机崩）。
- 修法（6aa83c3，只改测试）：esbuild onLoad 把 *.gen.ts 换成空壳 `module.exports = {}`，检查时也跳过它们。这些文件是纯数据、没有 import、不读挂载点，import 图不变（base / aholo 都是 208 个模块）。峰值约 180 MB，1 秒出结果；反向插静态 `import './mage_fx_d1'` 仍报 ✗（检测有效）。
- 注意：aholo gen 会改动已跟踪的 src/dlc/dlc1/forgecg.gen.ts，跑完要 `node gen-assets.mjs` 回 base 或 git checkout，别提交。
